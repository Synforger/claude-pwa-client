# 会話の自動の入れ替え

会話が長くなると context が埋まり、 応答が遅く高くなります。 自動の入れ替えは、 context が決めた割合に
届いた会話に「区切りで締めて、 次の会話へ引き継いで」 と頼み、 締め終えたら同じタブで新しい会話を
起動し直す仕組みです。 人が「終わり」 と言ったり、 タブを作り直したりしなくても、 会話が入れ替わります。

何を書き残して引き継ぐかは Claude の側 (= そのエージェントの `CLAUDE.md` など) が決めます。 この仕組みが
するのは、 頼む時機を見張ることと、 頼まれたらタブを起動し直すことの 2 つです。

既定では何もしません。 使うエージェントにだけ、 条件を設定します。

静かなタブの Claude を終わらせてメモリを返す仕組みは [眠り](sleep.md) です。 眠らせるのは `idle.context_pct`
より下のタブだけで、 その線を超えた静かなタブは入れ替えが引き受けます。

## 設定

`backend/config.json` の、 使いたいエージェントに `rollover` を足します。 階層ごとに変える時は、 エージェントの `tiers` に
書きます ([config.md](config.md) の `tiers`)。

```json
"agents": {
  "agent_a": {
    "cwd": "/path/to/agent_a",
    "launch_alias": "agent_a",
    "rollover": {
      "working": { "context_pct": 60 },
      "idle":    { "context_pct": 40, "minutes": 50 }
    }
  }
}
```

| 項目 | いつ頼むか |
|---|---|
| `working.context_pct` | context がこの割合 (%) に届いた時。 Claude が作業している最中でも、 手が空いていても |
| `idle.context_pct` と `idle.minutes` | 手が空いているタブの context がこの割合を超えていて、 会話がこの分数だけ動いていない時 |

- 片方だけ書いても構いません。 書いていない方の条件では頼みません
- 手が空いているタブでも、 `working.context_pct` に届いていれば `idle.minutes` を待たずに頼みます。 待つと、
  次に発話した時にその発話を古い会話が受けてしまうためです
- context の割合は、 画面の上部に出ている値と同じ物です
- 頼むのは 1 度に 1 つのタブだけです。 頼まれたタブが締めの作業をしている間は、 次のタブに頼みません
  (= 同じ作業ディレクトリを使う会話の締めが重なるのを避けます)。 作業中のまま 30 分記録が動かないタブ
  (= 道具の許可を待っている、 道具が止まった) は、 締めの作業をしていると数えません
- 同じ会話には、 頼んだ後に人がそのタブで発話するまで、 頼み直しません。 発話があっても、 前回頼んでから 5 分空くまでは頼みません
  (= 声で話し続けると、 発話のたびに頼みが届くのを避けるためです)。 頼むのに失敗した時は、 次の見回りでもう一度頼みます
- 静かな時間は、 会話の記録と、 その sub-agent の記録のうち新しい方から数えます (= 裏で sub-agent が動いている間は静かと数えません)

### 道具が裏で命令を走らせている時

会話が終わる時、 Claude Code は自分の道具が裏で走らせている命令 (= Bash の `run_in_background` と Monitor が
起こした命令と、 その下の子) を止めます (SIGTERM)。 入れ替えは会話を終わらせるので、 そのままでは長い試験や
build が途中で止まります。

- 見張りは、 Claude の下にそうした命令が残っているタブには、 どちらの条件でも頼みません。 次の見回りでまた見て、
  命令が終わっていれば頼みます。 待つ間は次のタブを見ます (= log の `rollover: held session=… background=<pid,…>`、
  命令の組が変わった時だけ)。 待つ間に context が埋まる時は、 Claude Code の自動の要約が受け持ちます
- working の割合 (`context`) を超えて待たせた会話には、 なぜ頼まないかを 1 回だけ知らせます。 1 行目は client の知らせの行で、
  block は `<rollover-held reason="context" context_pct="…" line="…">`、 本文は命令ごとの pid・経過・命令の頭と、
  会話より長く走らせる命令の起こし方です。 動いている Claude にだけ打ち、 眠ったタブは起こしません。 使用上限で止まった会話、
  上限の後の続きがまだの会話、 口座の止める線や移しの頼みが立っているタブには、 外れるまで送りません (= log の
  `rollover: told held …` と `rollover: notice deferred … reason=<limit|account|no_claude>`)。 1 つの会話に 1 回で、
  backend を再起動しても、 記録に知らせが在れば送り直しません。 静かな時間 (`idle`) で待たせた会話と、 もう頼んだ会話
  (= `tabs rollover` が命令を名指して断る) には送りません
- 見分けは、 Claude の直下の process のうち、 Claude Code の shell の snapshot (= `~/.claude` の下の `shell-snapshots` の folder の file) を読む
  shell です。 MCP や言語の server、 hook、 Claude が答える間の `caffeinate` は数えません。 推論中は、 今の道具の
  呼び出しの shell も同じ形なので、 その呼び出しが終わるまで待ちます
- 会話より長く走らせたい命令は、 普通の Bash で `nohup <命令> > <log> 2>&1 &` として起こします。 その呼び出しの
  shell がすぐ終わるので、 会話が終わっても残ります (= 入れ替えも待ちません)
- 起こす予約 (`ScheduleWakeup`) と定期実行では待ちません。 締めの中で Claude が扱えます

### 締めの手が止まった時

頼まれた Claude が締めを終えずに手を止めることがあります (= 人の返事を待っている、 締めの手順の途中で
止められた)。 見張りは、 そのタブが 30 分静かで、 締めのほかに区切りを妨げる物 (= 裏のコマンド・予約・
定期実行・通話・口座の振り分けの頼み) が無い時に、 **もう 1 回だけ**同じ封筒で頼みます (= log の
`rollover: asked … again=1`)。

2 回頼んでも締めずに 30 分静かなタブと、 上限で止まったタブは、 **頼みの期限切れ**です
(= `rollover: lapsed session=… asks=… limit_stop=…`、 会話ごとに 1 回)。 見張りはもう頼まず、 眠り・
止める線・逃げ先は、 そのタブを締めの途中と数えません。 入れ替えの線の上でも眠ります
([静かなタブの眠り](sleep.md))。 頼み直しの数は、 人がそのタブで発話すると 0 に戻り、 期限切れの後に
別のタブの連絡が届いた時も 0 に戻ります (= 新しい仕事が届いたので、 条件が立てばまた頼みます)。
- 設定は画面の「設定」から変えられ、変えた値は次の見回りから効きます ([設定の画面](settings-screen.md))。`config.json` を手で書き換えた時は、backend を再起動してください

`idle.minutes` は、 プロンプトキャッシュが生きているうちに締めさせたい時に、 その寿命より短く置きます
(= 例: 寿命が 60 分なら 50 分)。 見張りは 60 秒ごとなので、 頼むのが最大 60 秒遅れます。

見張りは、 どれかのタブで Claude が作業を始めた時 (= 人の発話でも、 別のタブからの連絡でも) にも、
60 秒を待たずに見回ります。 作業を始めたタブは、 その見回りでは作業中と数えます。 数秒で終わる作業
(= 連絡への短い返事など) が見回りの間に収まっても、 割合を超えていれば `working` の条件で頼みます。
作業を始めた時を知るのは Claude の `UserPromptSubmit` の hook で、 導入の手順で入れる hook に含まれています。

## 流れ

1. backend が、 条件の立ったタブの Claude へ**締めを頼む発話**を届けます
2. Claude は、 作業を区切りまで進め、 次の会話に要る物を書き残してから、 **起動し直す口**を呼びます
3. backend がそのタブの Claude を終了し、 口に渡された本文を**最初の発話**にして新しい会話を起動します

画面では、 1 と 3 の発話が「自動の入れ替え」 と付いた別の色の吹き出しで出ます。 それまでの会話は
タブに残ります。 画面を閉じている間に入れ替わった時も、 開くと締めを頼む発話から、 締めの作業、 新しい会話の
最初の発話までが続けて出ます。 フォークで作ったタブでも同じです。 終わった会話の記録は、 タブが入れ替わっても
閉じられても消しません。 古い記録は、 どのタブの物も経過日数と全体の容量で片付きます。

### 画面を長く閉じていた時の履歴

画面は、 タブを開くたびに、 最後に描き終えた位置から後ろの履歴を取り直します。 前の会話と今の会話をまたいで
数え、 取り直す行数は次の 3 通りです。

| 閉じていた間に書かれた行 | 取り直す範囲 | 画面の cache |
|---|---|---|
| 500 行まで | 直近 500 行 | 残して、 uuid で重ねる |
| 500 行を超え、 3000 行まで | 最後に描き終えた位置の直後から全部 | 残して、 uuid で重ねる |
| 3000 行を超える | 直近 3000 行 | 捨てて、 取り直した行だけで並べ直す |

3000 行を超えた時は、 古い cache と取り直した行の間に抜けが残るため、 画面は手元の cache
(= 画面のメッセージと、 ブラウザに保存した分) を捨てて、 取り直した直近 3000 行から並べ直します。 それより前の
会話は画面に出ませんが、 記録には残っています。 画面の位置が記録の終わりより先を指していた時
(= 記録が作り直された時など) は、 直近 500 行を取り直して cache を残します。

接続をつなぎ直した時の流し直しも同じ範囲を使います。 3000 行に届かなかった時は、 画面が履歴を取り直します。

### 締めを頼む発話

1 行目は固定です。 `reason` は `context` (= 作業中に割合へ届いた) か `idle` (= 静かなまま割合を超えている) です。

```
Automatic session rollover, sent by the client (the operator did not type this):
<session-rollover phase="close" reason="context" context_pct="62" idle_minutes="0">
Context is at 62%. Wrap up at the next stopping point and hand over: write down what the next session needs, then ask the client to start it (POST /sessions/<タブの id>/rollover, form field `text` = what the next session opens with).
</session-rollover>
```

[子のタブ](child-sessions.md) への発話は、 後ろの 2 文が替わり、 journal と口の代わりに、 子のメモの `## 引き継ぎ` を
今の仕事に書き直して `tabs rollover continue` (続ける物が無ければ `tabs rollover wait`) を実行するよう頼みます。

Claude が作業している最中に届いた発話は、 作業の合間に読まれます。

### 起動し直す口 (= タブの中の Claude が実行する)

```sh
curl -s http://127.0.0.1:8765/sessions/"$PWA_SID"/rollover -F 'text=<handover.txt'
```

| 項目 | 中身 |
|---|---|
| `text` | 新しい会話の最初の発話に入る本文。 次の会話が何から始めるかを書く |

port は backend を起動した port に合わせてください。 受け付けると `202` と `{"rolling": true}` を返し、
約 1 秒後にそのタブの Claude を終了します。 この口は、 締めを頼まれていない会話からも呼べます
(= Claude が自分の判断で会話を入れ替える)。 呼べるのは backend と同じ機械の中からだけです。

口は、 道具が裏で走らせている命令を確かめません (= 呼べば、 その命令は会話と一緒に止まります)。 エージェントの
plugin の命令 `tabs rollover` は、 頼む前に確かめ、 命令が在れば pid・経過・命令と次の手を出して頼みません。
同じ命令は、 そのタブが持つ動いている票のうち、 今の会話で 1 行も書き足していない票が在る時も、 票の id と題を出して頼みません ([票](tickets.md) の `tabs ticket mine --unsettled` と同じ検査)。

### 新しい会話の口座

[口座の逃げ先](account-fallback.md) を持つ口座のタブは、新しい会話を、そのタブが今動いてよい口座で立てます。
新しい会話はキャッシュを持たないので、口座を変えても失う物がありません。決め方は、眠ったタブが起きる時と同じです。
画面の ⟳ でタブをやり直した時も同じです。

| タブ | 新しい会話の口座 |
|---|---|
| 元の口座が空いている | 元の口座 (逃げ先へ移っていたタブは、ここで戻ります) |
| 元の口座が線か先回りの線に届いていて、逃げ先が空いている | 逃げ先 |
| どちらも線の上・使用率が分からない | 今の口座のまま ([止める線](account-hold.md) が区切りで止めます) |
| 固定したタブで元の口座にいる・逃げ先を持たない口座のタブ | 今の口座のまま |
| 眠っているタブ・止める線で止めたタブ | 対象外 (入れ替えは起きているタブの物) |

口座を変えた時は log に 1 行出ます。

```
new conversation: account session=ses_0123456789ab from=personal to=work
```

逃げ先へ移っていた間の会話の記録は、逃げ先の口座の folder に残ります。終わった会話の記録として履歴から開け、
会話の記録の 14 日の決まりで消えます。前の会話への区切りの頼み・止める頼み・「続けて」の借りは、新しい会話には
引き継ぎません。まだ要るなら、見回りが新しい会話に頼み直します。

### 新しい会話の最初の発話

```
Automatic session rollover, sent by the client (the operator did not type this):
<session-rollover phase="start">
口に渡された本文
</session-rollover>
```

エージェントに `launcher: true` を設定している場合は、 この発話が起動ラッパに
`--first-message-file` で渡ります ([config.md](config.md) の `agents`)。

[子のタブ](child-sessions.md) に親が `tabs new --model --effort` で値を選んでいた時は、 本文の後ろに同じ
`model=`・`effort=` の行が付きます (選ばれなかった物は付きません)。 子の最初の発話の `<child-start>` の塊は
入れ替えの後の会話には無いので、 起動ラッパはこの行から同じ値を読みます。 本文の後ろに置くので、 本文が同じ鍵の行を
書いていても、 後の行を採る読み方なら親の選びが勝ちます。

```
<session-rollover phase="start">
口に渡された本文
model=haiku
effort=low
</session-rollover>
```

子のタブの封筒は、 本文と `model=`・`effort=` の間に子の行を持ちます。 `child=1`、 `parent=<親のタブの id>`
(親のタブが在る時だけ)、 英語の 1 段落です。 段落は、 階層の journal と依頼は親の物である事、 子の仕事はメモに在る事、
続けるか待つかを言います。 起動ラッパは `tier=`・`model=`・`effort=` を今までどおり読めます。

```
<session-rollover phase="start">
tier=projects/<P>
mode=continue
child=1
parent=ses_0123456789ab
This tab is a child tab. …
model=haiku
</session-rollover>
```

## 人の発話との見分け

2 つの発話は、 人が画面から送る発話と同じ道 (= Claude の入力欄) で届くので、 会話の記録では人の発話と
同じ行になります。 見分けは 1 行目で付けます。 この行は自動の入れ替えの発話にだけ付き、 人の送信には
付きません。

人の発話だけを指示として扱う道具 (= 端末の入力を読んで判定する hook など) を使っている場合は、
この 1 行目で始まる発話を人の発話から外してください。 [タブどうしの連絡](agent-messages.md) の
1 行目と同じ扱いです。

## 引き継ぐ本文を検査する (任意)

[タブどうしの連絡](agent-messages.md) に検査 (= `agent_message_check`) を設定している場合は、
起動し直す口に渡された本文にも同じ検査が掛かります。 新しい会話は同じタブで同じように起動する今の会話の
続きなので、 宛先 (= `{session}`) には今の会話の id が渡ります。 今の会話の記録が見つからない時だけ、
どの会話の id でもない `rollover:<タブの id>` (= 何も読んでいない相手) が渡ります。

## 起きない時

| 見えること | 原因 |
|---|---|
| 条件を超えているのに頼まれない | そのエージェントに `rollover` が無い / 設定の後に backend を再起動していない / そのタブで Claude が動いていない / 別のタブが締めの最中 / その会話にはもう頼んである / 道具が裏で命令を走らせている (= log の `rollover: held`) |
| `tabs rollover` が「道具が裏で命令を走らせています」 で止まる | 会話が終わるとその命令が止まる。 終わるのを待つか、 止めてよければ止めてから打ち直す |
| 口が `rollover_unknown_session` を返す | その id のタブが無い |
| 口が `rollover_empty` を返す | 本文が空 |
| 口が `rollover_local_only` を返す | 別の機械から呼ばれた |
| 口が `agent_message_refused` を返す | 検査が本文を通さなかった。 理由が `reason` に入っている |
| タブが終了した後、 会話が始まらない | 起動に失敗している。 そのタブで発話を送ると、 開き直せる前の会話が在ればその会話が開き、 無ければ新しい会話が始まる |
