# 上限が戻った時の続き

使用量の上限で止まったタブは、そのままでは誰も続けさせません。起きているタブは次の発話まで待ち、60 分たつと
[眠り](sleep.md) に入り、眠ったまま起きません。この仕組みは、**上限が戻ったら、止まったタブに続けての連絡を
1 通送ります。** 眠っているタブは、この連絡で同じ会話のまま起きます。

設定はありません。全部の口座のタブが対象です。

## 止まったタブ

会話の最後が、Claude Code が上限で止まった時に書く行 (`isApiErrorMessage: true`、`error: "rate_limit"`、一時的な
混雑を示す `apiErrorIsTransient` が付かないもの) のタブです。この行の後に発話や返事が 1 つでも書かれれば、止まって
いるタブではなくなります。

## 戻った、の判定

タブの**今の口座**の最新の使用率の行 (`rate-limits.jsonl`) を、次の線と比べます。

| 口座 | 線 |
|---|---|
| [逃げ先](account-fallback.md) の設定がある口座 | その `at_pct` |
| 設定が無い口座 (個人の口座など) | 100% |

線以上で、その窓の `*_resets_at` をまだ過ぎていない窓が無くなり、かつ次のどちらかが言えた時に、続けさせます。

- 線に届いていた窓の `*_resets_at` が、**止まった時刻より後**に過ぎた
- 止まった後に書かれた新しい行が線を下回っていて、その止まりを**線に届いている間に見ていた**

どちらも言えない止まり (使用率が説明しない止まり) には送りません。同じ止まりが続くだけで、続けての連絡が
繰り返されるのを防ぐためです。

逃げ先の設定がある口座のタブは、上限の間は逃げ先へ移るのが先です。移せずに止まったまま残ったタブだけ、戻った
時にこちらが続けさせます。2 つの仕組みが同じタブに同時に手を出すことはありません。

## 送る手順

1. 止まった行の uuid を、タブの定義 (`session_meta.json` の `limit_resumed`) に**送る前に**保存します
2. タブが眠っていれば、連絡と同じ道 (`tabs send` と同じ起こし方) で、同じ会話を開き直します
3. 続けての連絡を入力欄に打って確定します。届かなかった時は uuid を消して、次の回にもう一度送ります

連絡は、自動の入れ替えと同じ 1 行目 (「client が送った、人が打っていない」と分かる行) で始まります。

```
<limit-resume account="personal">
The usage limit has ended. Carry on with the work you were doing before it stopped.
</limit-resume>
```

**1 回止まるごとに 1 通だけ**送ります。Claude が起きるまでの間に見回りがもう一度来ても、backend を再起動しても、
同じ止まりに 2 通目は送りません (保存した uuid と同じ止まりは飛ばします)。続けた後にまた上限で止まれば、新しい止まり
なので、また 1 通送ります。見回りは [自動の入れ替え](rollover.md) と同じ 60 秒ごとです。

Claude が動いていない、眠ってもいないタブには送りません (このために起動はしません)。

## 見え方

backend の log に、送るたびに 1 行出ます。

```
limit resume: session=ses_0123456789ab account=personal stop=2f6c… asleep=0 sent=True
```

## 動かない時

| 見えること | 原因 |
|---|---|
| 戻ったのに送られない | 使用率の行がまだ線以上 / その止まりを線に届いている間に見ておらず、`*_resets_at` も止まりより前 / 口座の行が `rate-limits.jsonl` に無い |
| 送られたのに止まったまま | 上限が実際には戻っていなかった (別の種類の上限など)。その止まりは新しい止まりになる。使用率の行が線を下回るまで、また送られることはない |
| 眠っているタブが起きない | `limit resume: ... sent=False` と、`client message:` の警告を見る (起動できなかった、または入力を受けられなかった) |
