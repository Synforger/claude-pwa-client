# 子のタブ

タブの中の Claude が、 仕事を渡すために別のタブ (= 子のタブ) を立てる仕組みです。 子のタブは自分の会話を
持つので、 立てたタブ (= 親) の会話が終わっても、 [自動の入れ替え](rollover.md) で起動し直しても回り続けます。
子は終わった時に [タブどうしの連絡](agent-messages.md) で親へ結果を返し、 親が受け取ってから閉じます。

Claude Code の sub-agent に近い使い方ですが、 sub-agent は親の会話の中でしか動けません。 子のタブは画面の
一覧に出る普通のタブなので、 人も中を開いて見られます。

## 立てる口 (= タブの中の Claude が実行する)

```sh
curl -s http://127.0.0.1:8765/sessions/"$PWA_SID"/children \
  -F title='build the parser' -F 'text=<task.txt'
```

| 項目 | 中身 |
|---|---|
| `agent_id` (任意) | 子のタブのエージェント (= `config.json` の `agents` の key)。 省くと、 親のエージェントの `child_agent`。 それも無ければ親と同じエージェント |
| `text` | 子のタブの最初の発話に入る本文 (= 渡す仕事) |
| `title` (任意) | 子のタブの名前。 省くとエージェントの既定の名前 |

port は backend を起動した port に合わせてください。 受け付けると、 立てたタブの記録 (= `GET /sessions` の
1 件と同じ形) に `started` (= 最初の発話を渡せたか) を足して返します。 呼べるのは backend と同じ機械の中から
だけです。

- 子のタブは親と同じアカウントで動きます
- 子のタブの通知は、 立てた時はオフです (= 進みは親への報告で届くため。 画面の ⚙ で入れ直せます)
- 子の記録は `parent_id` に親のタブの id を、 `child` に `true` を持ちます
- タブの id は自動の入れ替えでも変わりません。 子は親のタブの id 宛てに連絡を送れば、 親の今の会話に届きます

## 最初の発話

親のタブから届いた連絡と同じ封筒です ([agent-messages.md](agent-messages.md))。

```
Message from another session, relayed by the client (the operator did not type this):
<agent-message from="<親のタブの名前>" session="<親のタブの id>">
口に渡された本文
</agent-message>
```

エージェントに `launcher: true` を設定している場合は、 この発話が起動ラッパに `--first-message-file` で
渡ります ([config.md](config.md) の `agents`)。

## 子のタブだけ起動の仕方を変える

子用のエージェントを別に設定し、 親のエージェントの `child_agent` にその key を書きます。 例えば起動ラッパに
子のタブであることを伝える引数を付けると、 子のタブは軽い起動で始められます。

```json
"agents": {
  "agent_a":     { "cwd": "/path/to/agent_a", "launch_alias": "agent_a", "launcher": true, "child_agent": "agent_a_sub" },
  "agent_a_sub": { "cwd": "/path/to/agent_a", "launch_alias": "agent_a --child", "launcher": true, "display_name": "Sub-agent" }
}
```

子用のエージェントは、 画面の「新しい会話」 の一覧にも並びます。

## 数の上限

1 つのタブが同時に持てる子は、 既定で 5 つです。 `config.json` の `child_sessions_max` で変えられます。
子は同じアカウントの使用量を分け合うので、 上限を外すと一斉に立てた子が親のタブまで利用の制限に掛けます。
閉じた子は数から外れます。

## 閉じる

普通のタブと同じ `DELETE /sessions/<子のタブの id>` です。 画面の一覧の ⋯ からも閉じられます。

閉じると、 client がその子のために書いた物も一緒に片付きます。 片付くのは、 メモ (= `pages/<子の id>/memo.md`)、 雛形から
作ったまま手の入っていないトップページ、 それで空になった folder です。 子が自分で書いた説明のページは残ります。 子の
階層の folder と親の階層の folder の両方を見ます。

手の入っていないトップページかどうかは、 file の中身だけで決めます。 client がトップページを書いた時の中身の指紋を
子のタブの記録 (= `top_page_sha`) に残してあり、 閉じる時にページの今の中身がその指紋と同じなら、 立てた後に雛形が新しく
なっていても片付けます。 目次の部品を読む 1 行だけが足されたページも、 その行を除いて比べるので同じです。 指紋を持たない
子と、 指紋が合わない時は、 今の雛形で埋めた中身との比較になります。

## 眠らせる

報告を受けた子を、続きの仕事まで同じタブで待たせる時は、閉じずに眠らせられます。親のタブから
`tabs sleep <子のタブの id>` を打つと、その子の Claude が終わってメモリが空き、連絡が届くと同じ会話で起きます。
口は `POST /sessions/<親のタブの id>/children/<子のタブの id>/sleep` です。条件と待ち方は
[静かなタブの眠り](sleep.md#親が子のタブを眠らせる) にあります。眠った子も子の数に入ります。

## 子の一覧 (`tabs children`)

親のタブから `tabs children` を打つと、 そのタブが立てた子が 1 行ずつ出ます。

```
ses_a1b2  作業中  入力待ち  build the parser  ← 報告なしで止まっている
ses_c3d4  完了   Claude なし  fix the header
```

| 欄 | 中身 |
|---|---|
| 1 | 子のタブの id |
| 2 | 子のメモ (= `pages/<子の id>/memo.md`) の状態の行。 `作業中` / `完了` / `詰まり`。 `tabs report` が書き換え、 報告した子へ親の連絡が届くと backend が `作業中` に戻す (= 次の仕事を持っている)。 仕事を渡さない連絡 (= 受け取りの知らせなど) は `tabs send <子> <file> --no-work` で送り、 メモはそのまま |
| 3 | 子の Claude が今していること。 下の表の 5 つの語 |
| 4 | 子の題 |
| 5 | メモが `作業中` のまま Claude が `入力待ち` の子にだけ付く `← 報告なしで止まっている` (= 下の止まった子の見回りと同じ判定) |

| 第 3 欄 | 意味 |
|---|---|
| `作業中` | Claude が答えている途中 |
| `裏の仕事待ち` | Claude は答えていないが、 区切りでもない。 裏のコマンド (`run_in_background` など) の終わり、 起こす予約、 定期の予約、 道具の結果を待っている。 待っている物が終われば Claude が自分で続ける |
| `入力待ち` | Claude は動いていて、 区切りに居る (= 待っている物が無く、 次の発話を待っている) |
| `眠り` | [眠らせた](sleep.md) 子。 連絡が届くと同じ会話で起きる |
| `Claude なし` | Claude が動いていない |

`tabs children --summary` は 1 行です (`children: 2 (作業中 1 / 完了 1 / 詰まり 0 / 静か 1)`)。 最後の `静か` は、 5 欄目の
印が付いた子の数です。

第 3 欄と第 5 欄は、 backend が今その子を区切りと見るか (= `GET /sessions/{親}/children`。 止まった子の見回りと同じ判定)
で決まります。 backend から答えが取れない時は、 答えていない Claude を `裏の仕事待ち` として出し、 印を付けません
(= 止まったと言い切れないため)。

## 止まった子の見回り

子が報告しないまま止まると、 親は気づけません。 上限で止まった子も、 返事を書き終えて入力待ちになった子も、 親の会話には
何も届きません。 client は 1 分ごと (= [自動の入れ替え](rollover.md) と同じ間隔) に子のタブを見回り、
**報告せずに止まった子があれば、 親のタブへ連絡を 1 通**送ります。 設定はありません。

見回りが対象にする子は、 メモの状態が `作業中` で、 眠っておらず、 親のタブが残っている子です。 そのうえで、 次の全部が
**続けて 2 回の見回り**で、 子の会話の記録の同じ最後の行のまま見えた時に送ります。

- Claude が動いている
- 答えの途中・裏で走るコマンド・道具の結果待ち・起こす予約・定期の予約・声の通話・入れ替えのどれも無い
  (= [眠りの判定](sleep.md) を親が手で頼んだ時と同じ。 上限の止まりがそう見せる物は除く)

送る連絡は、 [上限が戻った時の続き](limit-resume.md) などと同じく client が書いた物で、 1 行目は
`Sent by the client (the operator did not type this):` です (= 操作者の発話と区別できる行)。 本文は英語の決まった形です。

```
Sent by the client (the operator did not type this):
<child-stopped child="ses_a1b2" title="build the parser" reason="idle">
This child is waiting for input and has not reported. …
</child-stopped>
```

| `reason` | いつ | 本文 |
|---|---|---|
| `limit` | 会話の記録に上限の止まり、 または Claude Code がまだ果たしていない続きの予約がある | 上限が戻ると続けさせられる (Claude Code 自身か、 子の Claude を起動し直した後なら client。 [上限が戻った時の続き](limit-resume.md#止まったタブ)) ので、 止まったままの時だけ手を出す |
| `idle` | それ以外 | 報告せずに入力待ちで止まっている。 会話の終わりを読み、 連絡を送るか閉じる |

同じ止まりには 1 通です。 止まりの印は子の会話の記録の最後の行の時刻で、 子のタブの定義の `stop_told_at`
([data-schemas.md](data-schemas.md)) に残すので、 backend を再起動しても繰り返しません。 子がまた動いて止まれば、
最後の行の時刻が進むので、 新しい止まりとして 1 通送ります。 連絡が届かなかった時は印を戻し、 次の見回りで送り直します。

送るたびに backend の log に 1 行出ます。

```
child watch: session=ses_a1b2 parent=ses_parent reason=idle sent=True
```

## 画面の一覧

子のタブは、 フォークのタブと同じように親の直下に字下げして並び、 名前の前に `↳` が付きます (= フォークは `⑂`)。
下にタブを持つ行の左の `▾` を押すと、 その下を畳みます (= `▸` で開く)。 畳んだ行には隠れているタブの数が
出ます。 畳んだかどうかは、 端末ごとに覚えます。

## 届ける前に検査する (任意)

[タブどうしの連絡](agent-messages.md) に検査 (= `agent_message_check`) を設定している場合は、 立てる口に
渡された本文にも同じ検査が掛かります。 子は親の仕事の続きとして扱い、 宛先 (= `{session}`) には親の今の
会話の id が渡ります。 親の会話の記録が見つからない時だけ、 どの会話の id でもない `child:<親のタブの id>`
(= 何も読んでいない相手) が渡ります。 検査が通らなかった時は、 タブを立てません。

子を親と違う作業ディレクトリで動かす場合は、 親が読めて子が読めない物が本文に入らないよう、 起動する側で
確かめてください (= 検査は、 子が親と同じ物を読める前提で通します)。

## 立たない時

| 見えること | 原因 |
|---|---|
| 口が `child_session_unknown_parent` を返す | その id の親のタブが無い |
| 口が `invalid_agent_id` を返す | `agent_id` か、 親のエージェントの `child_agent` が `agents` に無い |
| 口が `child_session_empty` を返す | 本文が空 |
| 口が `child_session_limit` を返す | 親の子が上限に届いている。 終わった子を閉じてから立てる |
| 口が `child_session_local_only` を返す | 別の機械から呼ばれた |
| 口が `agent_message_refused` を返す | 検査が本文を通さなかった。 理由が `reason` に入っている |
| `started` が `false` | タブは立ったが、 最初の発話を渡せなかった。 子のタブを開いて発話を送ると、 それが最初の発話として会話が始まる |
