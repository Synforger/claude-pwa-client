# 静かなタブの眠り

使っていないタブの Claude は、何もしていなくてもメモリを持ち続けます (1 本で 200〜460 MB)。眠りは、静かな
タブの Claude を終わらせてメモリを返し、そのタブに触った時や連絡が届いた時に、**同じ会話**で起こす仕組みです。

眠らせても、会話は失われません。会話の記録は残り、起こす時は `claude --resume` でその会話を開き直します。
プロンプトキャッシュは Claude の外 (API の側) にあり、最後に使ってから 1 時間で切れます。眠らせても切れる時刻は
変わらないので、1 時間以内に起こせば会話の全部がキャッシュから読まれ、1 時間を過ぎれば、眠らせなかった場合と同じだけ
読み直します。眠らせて増えるのは、起こす時の起動の時間だけです。

既定では何もしません。使うエージェントにだけ、設定を足します。

## 設定

`backend/config.json` の、使いたいエージェントに `sleep` を足します。

```json
"agents": {
  "agent_a": {
    "cwd": "/path/to/agent_a",
    "launch_alias": "agent_a",
    "sleep": { "minutes": 60, "pressure_minutes": 10 }
  }
}
```

| 項目 | 意味 |
|---|---|
| `minutes` | タブの会話がこの分数だけ何もしていなければ、そのタブの Claude を眠らせる。1 以上の整数 |
| `pressure_minutes` | 機械のメモリが逼迫している間だけ使う、短い分数 ([メモリの逼迫](#メモリの逼迫))。1 以上 `minutes` 以下の整数。書かなければ、逼迫の時も早く眠らせない |

- `minutes` は 60 以上を勧めます。それより短いと、少し手を離しただけのタブも眠り、触るたびに起動を待つことになります
- 整数でない値や 1 未満の値を書いたエージェントは、眠らせません
- 設定は画面の「設定」から変えられ、変えた値は次の見回りから効きます ([設定の画面](settings-screen.md))。`config.json` を手で書き換えた時は、backend を再起動してください
- 見回りは、[自動の入れ替え](rollover.md) と同じ 60 秒ごとです

## 眠らせる条件

次の**全部**がそろったタブだけを眠らせます。1 つでも欠けたタブは、そのまま起きています。

| 条件 | 欠けた時の理由 (log) |
|---|---|
| そのタブで Claude が動いている | `claude_not_running` |
| Claude が端末の入力を受けられる状態にある (起動の途中ではない) | `starting` |
| Claude が返事を作っていない。返事の後ろに、まだ処理されていない発話も積まれていない | `turn_open` |
| そのタブの会話の記録が見つかる | `no_record` |
| 会話の記録と、その会話の子の Agent の記録 (記録と同じ名前の folder の `subagents/`) のどちらにも、`minutes` 分のあいだ新しい行が無い。行の新しさは、行が持つ時刻 (`timestamp`) で測る | `not_quiet` |
| コンテキストの割合が、そのエージェントの `rollover.idle.context_pct` 未満 (入れ替えの設定が無いエージェントは、この条件を見ない) | `context_at_rollover_line` |
| Claude のプロセスの下に、言語の道具以外のプロセスが 1 つも無い | `processes_running` |
| 最後の発話より後に `ScheduleWakeup` で起きる予約をしていない | `wakeup_scheduled` |
| 会話の中で `CronCreate` で作った定期実行が、`CronDelete` で消されずに残っていない | `cron_scheduled` |
| 会話の最後の行が、結果のまだ無い道具の呼び出しではない (人の答えや許可を待っていない) | `awaiting_tool_result` |
| 声の通話中ではない | `voice_call` |
| 自動の入れ替えの途中 (締めを頼んだ後、新しい会話が起動するまで) ではない | `rolling_over` |
| 口座の振り分けが、そのタブに区切りや止めを頼んでいない。「続けて」を返す借りも無い ([account-fallback.md](account-fallback.md)・[account-hold.md](account-hold.md)) | `account_pending` |
| 口座の振り分けが、そのタブを今扱っていない | `claimed` |

- コンテキストの割合は、画面の上部に出ている値と、自動の入れ替えが使う値と同じです。`rollover.idle.context_pct`
  を超えたタブは、眠らせずに入れ替えが引き受けます
- 言語の道具は、作業していなくても Claude の下に居続けるので数えません: `clangd`・`pyright-langserver`・
  `typescript-language-server`・`gopls`・`rust-analyzer`・`sourcekit-lsp`。それ以外のプロセスは作業の印です。
  返事を作っている間に居る `caffeinate` も、走っているコマンドも含みます
- 口座の振り分けは眠ったタブを見ないので、頼みや借りのあるタブを眠らせると、その頼みが宙に浮きます。そのタブは
  振り分けが片付けるまで起きています。振り分けが自分でタブを止める時と、親の `tabs sleep` は、この条件を見ません
- `ScheduleWakeup` の予約と `CronCreate` の定期実行は、Claude が終わると消えます。眠らせると予約した作業が
  起きなくなるので、残っているタブは眠らせません。一度しか動かない `CronCreate` が動き終えた後も、
  `CronDelete` で消さない限り残っているものとして数えます

静かな時間を file の更新時刻で測らないのは、動いている Claude が、行を足さずに自分の会話の記録を書き換えることがあるからです。更新時刻で測ると、何時間も何もしていないタブが、いつまでも静かになりません。時刻を持つ行が 1 つも無い記録だけは、file の更新時刻で測ります。

眠らせなかった理由は、同じ理由が続いている間は log に 1 回だけ出ます。

```
sleep: awake session=ses_0123456789ab reasons=not_quiet,processes_running
```

## 眠らせる手順

1. 上の条件を、眠らせる直前にもう一度すべて確かめます
2. 会話の記録の file が在り、最後の行が改行で終わっていることを確かめます
3. 起こす先の会話の id と記録の path を、タブの定義 (`session_meta.json`) に保存します
4. Claude に終わるよう頼み (`SIGTERM`)、終わるのを待ちます。**強制終了はしません。** 20 秒待っても終わらなければ、
   保存した印を消して眠らせるのをやめ、そのタブは起きたままにします。頼んだ Claude がその後で終わり、端末にシェルが
   残っても、次の発話はそのタブの前の会話を開き直します (= [agent-messages.md](agent-messages.md) の起動の表)
5. Claude が終わってから、タブの端末 (tmux の session) ごと閉じます
6. log に 1 行出します。報告を終えた子には `reported=1`、メモリの逼迫で眠らせたタブには `pressure=1`、親の
   `tabs sleep` には `by_hand=1` が最後に付きます

```
sleep: session=ses_0123456789ab claude_sid=7a1c9e2e-1111-2222-3333-444455556666 idle_min=75 context_pct=22
```

1 で確かめ始めてから 5 で端末を閉じ終えるまでの間 (最大 25 秒) に、別のタブの連絡や client の連絡が届くと、
眠らせ終わるのを待ってから、眠ったタブとして届けます (起こして届けるか、[account-hold.md](account-hold.md) の
決まりで預かります)。待たずに打つと、終わりかけの Claude に打たれて消えるためです。

端末ごと閉じるのは、眠ったタブを、機械の再起動の後と同じ「端末ごと無いタブ」として起こすためです。端末にシェルだけが
残ったタブも、次の発話で前の会話を開き直します。新しい会話になるのは、開き直す会話が無い時と、⟳ でやり直した直後だけです。

起こす途中 (= 開き直しを打ってから Claude が起動を知らせるまで) に届いた発話は、backend が預かります。Claude の画面が
出てから、届いた順に 1 通ずつ打ち、それぞれ会話の記録に載ったかを確かめます (= 連絡の受け取りの確かめと同じで、入力欄に
残った文には Enter を送り直します)。画面から送った発話が最後まで載らなければ、画面のその吹き出しに「届いていない」が出て、
文が入力欄へ戻ります (= 送った時は「預かった」と答えているので、後から SSE の `send_failed` で知らせます)。その間は、
起動の命令を重ねて打ちません。機械が重くて起動に何分かかっても、10 分までは待ちます。10 分たっても Claude が起動を
知らせなければ、その起動をあきらめ、預かった発話でもう一度起動します。

## 報告を終えた子

子のタブが `tabs report done` で報告すると、子のメモの状態が `完了` になります。見回りは、そういう子を `minutes`
を待たずに眠らせます。親が次の仕事を送れば、同じ会話で起きて続けます。条件は上の表に次の 3 つを足し、1 つを外した物です。

- 起こされた後か起動の後に、何かに答えている (会話に、起動の時刻より新しい行がある)。起こされた直後で、まだ連絡を
  受け取っていない子は眠らせません。欠けた時の理由は `not_answered_since_start`
- その後で 5 分、会話にも子の Agent の記録にも新しい行が無い。答えの最後と、裏で走らせた Agent を待つためです (`not_quiet`)
- 使用量の上限で答えが止まった子は、その止まりを区切りとして眠らせます。上限が明けても「続けて」は送りません
  ([limit-resume.md](limit-resume.md))。報告を終えた子には、続ける仕事が無いためです
- 外す条件: コンテキストが入れ替えの線を超えていても眠らせます (`tabs sleep` と同じ)

`--no-work` の連絡で起こした子は、答えた後もメモが `完了` のままなので、5 分後にまた眠ります。仕事を渡す連絡では
メモが `作業中` に戻り、普段の `minutes` の決まりに戻ります。報告が `stuck` の子 (`詰まり`) は、親がすぐ返すので、
普段の決まりのままです。

## メモリの逼迫

機械のメモリが足りない間は、`pressure_minutes` を書いたエージェントのタブを、`minutes` より早く眠らせます。

- 逼迫は、OS のメモリの判定 (macOS の `kern.memorystatus_vm_pressure_level`。Activity Monitor のメモリプレッシャーの
  元の値で、1 正常・2 警告・4 危険) が、続けて 2 回の見回りで 2 以上の時です。眠らせた後もしばらく値が下がらないので、
  1 回の高い値では動きません。macOS 以外では読まず、逼迫しないものとして扱います
- 1 回の見回りで眠らせるのは 1 本だけで、`pressure_minutes` 以上静かなタブのうち、一番長く静かなタブです。逼迫が
  続く間、1 分に 1 本ずつ進みます。ほかの条件は上の表のままで、入れ替えの線を超えたタブは選びません
- 見回りは、判定の値が変わった時と、前の見回りから swap を 1 MB 以上読み戻した時に、log に 1 行出します。
  固まったと感じた時刻と並べて、逼迫の判定が上がっていたかを確かめられます

```
sleep: memory level=2 swapins_mb=340 swap_used_mb=9867
```

`swapins_mb` は `vm_stat` の `Swapins` (swap から読み戻したページの数) の差です。`psutil` の `swap_memory().sin`
は macOS では file の読み込みも数えるので使いません。

## 親が子のタブを眠らせる

子のタブを立てた親は、その子を今すぐ眠らせられます。報告を受けて、続きの仕事まで同じタブで待たせる子に使います。
静かな時間を待たずにメモリを返せます。眠り方と起こし方は、上の見回りの眠りと同じです。

```
tabs sleep <子のタブの id>
```

口は `POST /sessions/<親のタブの id>/children/<子のタブの id>/sleep` で、同じ機械の中からだけ使えます。親の子でない
タブは眠らせません。エージェントの設定に `sleep` が無くても使えます。

見回りとの違いは次の 3 つです。

- 会話が静かな時間を待ちません
- コンテキストが入れ替えの線を超えた子も眠らせます。起きた後は、自動の入れ替えがいつもどおり引き取ります
- 子が答えを書いている間、その答えのコマンドが走っている間、起動の途中、道具の結果を待っている間は、最大 60 秒
  待ちます。報告した直後の子は、まだ答えの最後を書いているためです

ほかの条件 (起こす予約、定期の予約、声の通話、入れ替えの最中など) が当たる時は、待たずに `409` で断り、理由を
`params.reasons` に返します。`tabs sleep` は理由を日本語で出します。log の 1 行の最後に `by_hand=1` が付きます。

眠った子も、閉じるまでは子の数に入ります (`child_sessions_max` を書いている時、その数に当たります)。

## 起こす

起こすのは、端末ごと無いタブを起動する、今までの道です。

- 人がそのタブを開いて発話を送る
- 別のタブから `tabs send` で連絡が届く
- `POST /pty/<タブの id>/send` で発話が届く

起動は、保存した会話の id で `--resume` します (`launcher: true` のエージェントは `<launch_alias> --resume <id>`)。
タブの Claude が動いて入力を受けられるようになると、保存した印は消え、log に 1 行出ます。

```
sleep: woke session=ses_0123456789ab claude_sid=7a1c9e2e-1111-2222-3333-444455556666 bound=7a1c9e2e-1111-2222-3333-444455556666
```

`claude_sid` は保存していた会話、`bound` は起きたタブが実際に結んだ会話です。2 つが食い違う時は、log が警告で出ます。

静かな時間は、次の 3 つの**一番新しい物**から数えます。古い会話を開き直した直後のタブは、まだ何も書いていなくても、静かな時間が 0 から始まります (そうしないと、最後の行が古いので 1 分後に眠り直します)。

- 会話の記録の最後の行の時刻
- 今そのタブで動いている Claude が起動した時刻 (起こした時・新しく始めた時。OS が持つので、backend を再起動しても残ります)
- そのタブで会話が開かれた時刻 (`SessionStart`。Claude の中の `/resume` で会話を切り替えた時も含みます。backend を再起動すると忘れます)

- 眠っている間に口座を移したタブは、保存した会話を開きません (別の口座の folder にある会話は開けないため)
- 眠っているタブを「作り直す」(restart) と、保存した会話は使わず、新しい会話を始めます

## 見え方

- `tabs list` の状態に `眠り` と出ます。まだ一度も起動していないタブの `未起動` とは分かれます
- 画面の会話の一覧で、眠っているタブの名前の後ろに 💤 が付きます

## 起きない・眠らない時

| 見えること | 原因 |
|---|---|
| 静かなのに眠らない | log の `sleep: awake ... reasons=` を見る。理由は上の表の通り |
| 理由が出ない | そのエージェントに `sleep` が無い / 値が 1 以上の整数でない / 設定の後に backend を再起動していない |
| 報告を終えた子が眠らない | log の理由が `not_answered_since_start` なら起こされた後にまだ何も受け取っていない。`account_pending` なら口座の振り分けの頼みか借りが残っている |
| メモリが足りないのに早く眠らない | そのエージェントに `pressure_minutes` が無い / `minutes` より大きい。log の `sleep: memory level=` が 2 以上を続けて出していない |
| `sleep: ... left awake` が出る | Claude が 20 秒以内に終わらなかった。そのタブは起きたまま。後から Claude が終わっても、次の発話で前の会話が開き直される (log の `tab without a claude: reopened`) |
| `sleep: the record is missing or ends in a partial line` が出る | 会話の記録が無い、または最後の行が書きかけ。次の見回りでもう一度見る |
| 起こしたら別の会話になった | log の `sleep: woke ... bound=` が保存した `claude_sid` と違う。直前に同じタブの `fork:` の行があれば、口座の移し替えで会話が写されただけで、中身は同じ会話。無ければ、そのタブで起きた会話の記録を確かめる |
| 発話してもしばらく何も起きない | 起動の途中で、発話は預かられている (log の `launch in flight: holding the message`)。Claude が起動を知らせると打たれる。10 分たっても起動しなければ `launch given up` が出て、もう一度起動する |
