# 口座の逃げ先

口座の使用量が上限に近づいたら、その口座のタブを別の口座へ移して作業を続けさせ、上限が戻ったら元の口座へ戻す
仕組みです。タブは同じまま (タブの id・名前・親子の関係は変わりません)、動く口座だけが変わります。

既定では何もしません。使う口座にだけ、設定を足します。タブを移さずに止めたい時は、[口座の止める線](account-hold.md)
です (1 つの口座はどちらか一方です)。

> **想定している使い分け**: 勤務先から支給された口座と自分の口座のように、**元々別の主体に属する口座**どうしの
> 切り替えです。1 人が上限を回避する目的で複数の個人契約を回す使い方は想定していません
> ([config.md](config.md) の `accounts` を参照)。

## 設定

`config.json` の、移したい側の口座に `fallback` を足します。

```json
"accounts": {
  "work": {
    "display_name": "Work",
    "env": { "CLAUDE_CONFIG_DIR": "~/.claude-work" },
    "fallback": { "to": "personal", "at_pct": 95 }
  },
  "personal": { "display_name": "Personal", "env": {} }
}
```

| 項目 | 意味 |
|---|---|
| `to` | 逃げ先の口座 (`accounts` のキー) |
| `at_pct` | この使用率 (%) 以上になった口座のタブを移す。1 以上 100 以下の整数。既定は無い。5 時間の窓の線で、`seven_day_at_pct` に書かない曜日の 7 日の窓の線でもある |
| `seven_day_at_pct` | 7 日の窓の線を曜日ごとに変える表 (任意)。曜日の名前から 1 以上 100 以下の整数への対応で、書いた曜日だけが変わる |

- 向きは「`fallback` を書いた口座 → 逃げ先」の 1 本だけです。**逃げ先の口座のタブは、その口座が上限でも移しません**
- 次の `fallback` は無いものとして扱い、起動時に log へ警告を 1 行出します
  - `to` が `accounts` に無い、または口座自身
  - 逃げ先の口座が自分の `fallback` を持っている (逆向きと、つながった連鎖)
  - `at_pct` が 1〜100 の整数でない (書いていない場合も含む)
  - `seven_day_at_pct` が表でない、曜日の名前でない項目がある、値が 1〜100 の整数でない
- 逃げ先の口座の使用率は見ません。逃げ先は使い切ります
- 設定は画面の「設定」から変えられ、変えた値は次の見回りから効きます ([設定の画面](settings-screen.md))。`config.json` を手で書き換えた時は、backend を再起動してください
- 見回りは、[自動の入れ替え](rollover.md) と同じ 60 秒ごとです

### 7 日の線を曜日ごとに変える

7 日の窓の線だけを、曜日ごとに変えられます。5 時間の窓の線は `at_pct` のままです。

```json
"fallback": {
  "to": "personal",
  "at_pct": 95,
  "seven_day_at_pct": { "mon": 70, "tue": 76, "wed": 82, "thu": 88, "fri": 94, "sat": 100, "sun": 70 }
}
```

- 曜日の名前は `mon` `tue` `wed` `thu` `fri` `sat` `sun` です
- 書いた曜日だけが変わります。書いていない曜日と、`seven_day_at_pct` を書いていない口座は、`at_pct` を使います
- 曜日は backend が動く機械の地方時で決め、0:00 に切り替わります
- 移す時も、移ったタブを戻す時も、その時刻の曜日の線を使います。同じ使用率でも、曜日が変わって線が使用率を
  上回れば、戻ります

## 移す条件

次の**全部**がそろったタブを移します。

| 条件 | 内容 |
|---|---|
| 元の口座が線に届いている | その口座の最新の使用率の行 (`rate-limits.jsonl`) で、5 時間が `at_pct` 以上か、7 日がその曜日の線 (上の「7 日の線を曜日ごとに変える」) 以上のどちらかで、その窓の `*_resets_at` をまだ過ぎていない。口座の行が 1 つも無い時は何も言えないので移さない |
| タブが元の口座で動いている | すでに逃げ先へ移っているタブは対象外 |
| タブが止めても壊れない区切りにある | [眠り](sleep.md) の判定を「親が手で眠らせる時」の形で使う (下の表) |
| タブが眠っていない | 眠っているタブを移すと起こしてしまうので、見回りでは移さない。起こす時に移す (下) |

区切りの判定は、[眠り](sleep.md) の `judge(..., by_hand=True)` です。**60 分の静かな時間は待たず、入れ替えの線
(`rollover.idle.context_pct`) も見ません。** 次のどれかに当たるタブは移さず、当たらなくなった次の回に移します。

| 当たる条件 | 理由 (log) |
|---|---|
| そのタブで Claude が動いていない | `claude_not_running` |
| Claude が起動の途中 | `starting` |
| Claude が返事を作っている、または積まれた発話がある | `turn_open` |
| 会話の記録が見つからない | `no_record` |
| Claude のプロセスの下に、言語の道具以外のプロセスがある (裏のコマンド) | `processes_running` |
| 起こす予約 (`ScheduleWakeup`) が残っている | `wakeup_scheduled` |
| 定期の予約 (`CronCreate`) が残っている | `cron_scheduled` |
| 会話の最後が、結果のまだ無い道具の呼び出し (結果待ち) | `awaiting_tool_result` |
| 声の通話中 | `voice_call` |
| 自動の入れ替えの最中 | `rolling_over` |

**ターンの途中で上限に当たって止まったタブは、止まったこと自体を区切りとして移します。** 会話の最後が、
Claude Code が上限で止まった時に書く行 (誤りの行か知らせ。形は [上限が戻った時の続き](limit-resume.md#止まったタブ))
のタブです。この場合、止まったことで残る見かけだけを見ません:
返事を作っているように見えること (`turn_open`)、結果の無い道具の呼び出し (`awaiting_tool_result`)、起動の途中
(`starting`)。**裏のコマンド・起こす予約・定期の予約・声の通話・入れ替えの最中・Claude が動いていないこと
は、止まったタブでも待ちます**(移すと消えるものを消さないため)。判定は上の表と同じ 1 か所で、止まったタブの
時だけ上の 3 つを外します。

区切りに当たらなかった理由は、同じ理由が続いている間は log に 1 回だけ出ます。

```
account fallback: waits session=ses_0123456789ab account=work reasons=turn_open,processes_running
```

## 移す手順

1. 元の口座が線に届いていることと、タブが区切りにあることを、移す直前に確かめます
2. タブの会話を、**逃げ先の口座の** projects folder に新しい会話として書きます
   - 止まっていないタブ: 最後の「終わったターン、または人の発話」まで
   - 止まったタブ: そのターンの道具の結果までを残し、上限で止まった時の行だけを落とす
3. 設定に `lineage_hook` があれば、その命令を 1 回呼びます ([config.md](config.md))。失敗した時はタブに触らず、
   書いた会話を消して、次の回にもう一度試します
4. タブの Claude を止め、同じタブを、書いた会話の `--resume` で立て直します
5. タブの定義 (`session_meta.json`) に、本来の口座 (`fallback_from`) と、書いた会話の path (`fallback_copy`) を保存します
6. **止まっていたタブには、続けての連絡を 1 通送ります。** 会話の最後は止まった所でなくても、Claude Code が上限で予約した続きがまだ果たされていないタブ (上限の後に裏の仕事の知らせへ答えて区切りに来たタブなど) も同じです。Claude を立て直すとその予約は消えるので、代わりに送ります ([上限が戻った時の続き](limit-resume.md#止まったタブ))。区切りを頼んだタブにも、理由の欄を変えた同じ連絡を 1 通送ります ([答え続けているタブ](#答え続けているタブ))。それ以外のタブには何も送りません

続けての連絡は、client の連絡の 1 行目 (「client が送った、人が打っていない」と分かる固定の行) で始まります。

```
Sent by the client (the operator did not type this):
<account-move from="work" to="personal" reason="limit">
A usage limit stopped this session, so the client moved it to another account. Carry on with the work you were doing before it stopped.
</account-move>
```

### 画面から手で移す時

画面のタブの口座の札から移す時 (`POST /sessions/<タブの id>/account`) は、線も区切りも確かめずに、上の 2〜5 と同じ
手順ですぐ移します。続けての連絡は送りません。Claude を立て直すので、その Claude が裏で動かしていたコマンドは
終わります。立て直した Claude は、終わったコマンドの知らせを会話に書いて入力を待ちます。その知らせには答えないので、
タブは応答中とは数えません。子のタブなら、[止まった子の見回り](child-sessions.md#止まった子の見回り)が親へ知らせます。

どこかの手順が失敗した時、タブは元の口座のまま残り、log に理由が 1 行出ます。

```
account fallback: could not move session=ses_0123456789ab from=work to=personal: <理由>
```

### 眠っているタブ

見回りは眠っているタブを移しません (移すと起こしてしまうため)。眠っているタブが起きる時に、元の口座が線に届いて
いれば、その場で逃げ先へ移してから起こします。眠っているタブは、眠った時点で区切りにあります。

## 答え続けているタブ

返事を作り続けているタブ (`turn_open`) は、いつまでも区切りに来ません。口座が線を超えているのに会社の口座を
使い続けてしまうので、**区切りに来てくれるよう、client が 1 回だけ頼みます。** 移すのは頼んだ後も今までどおり、
見回りが区切りで行います。

頼む条件は、次の**全部**です。

| 条件 | 内容 |
|---|---|
| 移す条件がそろっている | 元の口座が線に届き、タブが元の口座で動いていて、固定されていない |
| 区切りに当たらない理由に `turn_open` がある | 返事を作っている最中。裏のコマンドだけ・起こす予約だけ・声の通話だけで止まっているタブには頼まない |
| 上限で止まったタブではない | 止まったタブは、止まったことが区切りなので、そのまま移す |
| 眠っていない | 眠っているタブは起こす時に移す |
| この「線を超えている間」に、まだ頼んでいない | 下の印 |

連絡は、client の連絡の 1 行目で始まります。作業中のタブへは、道具の呼び出しの合間に取り込まれます。

```
Sent by the client (the operator did not type this):
<account-move phase="pause" from="work" to="personal">
使用量が線を超えたので、このタブを Personal の口座へ移します。今の作業を区切りの良い所まで進めて、この返事を終えてください。移した後に、続きを頼む連絡が届きます
</account-move>
```

- **1 回の「線を超えている間」に 1 タブ 1 通です。** 頼んだ時刻をタブの定義 (`session_meta.json`) の
  `pause_asked_at` に残すので、backend を再起動しても 2 通目は送りません。口座が線を下回った時、タブを移した時、
  タブを固定した時に印を消します。次に線を超えた時は、また 1 通送ります
- 連絡が届かなかった (Claude を起こせない・受け取らない) 時は印を残さず、次の回にもう一度頼みます
- **頼んだタブが区切りに来たら、見回りがそのまま移し**、移した後に続けての連絡を 1 通送ります。上限で止まった
  タブへの連絡と同じ形で、理由の欄だけが `pause` です。頼んでいないタブが区切りで移った時は、何も送りません

```
Sent by the client (the operator did not type this):
<account-move from="work" to="personal" reason="pause">
口座を移しました。止める前の作業を続けてください
</account-move>
```

- **頼んでから 10 分たっても区切りに来ないタブには、もう送りません。** log に 1 行だけ出します。その後そのタブが
  区切りに来れば、移して、続けての連絡を送ります

```
account fallback: asked to pause session=ses_0123456789ab account=work
account fallback: no break after asking to pause session=ses_0123456789ab account=work waited_sec=612
```

## 戻す

移っているタブは、元の口座が**その時刻の線を下回った**か、**線に届いていた窓の `*_resets_at` を過ぎた**ら、同じ区切りの
判定で元の口座へ戻します。手順は移す時と同じで、向きだけが逆です。止まっていたタブには、同じ形の続けての連絡を
1 通送ります。

- 戻した時、**逃げ先の口座の folder に client が書いた会話の写し (`fallback_copy`) は、client 自身が消します。**
  消すのは、設定した口座の projects folder の直下にある `.jsonl` だけです。タブの会話の記録は消しません
- 全部のタブが逃げ先へ移っている間は、元の口座に新しい使用率の行が増えません。そのため戻るのは、線に届いていた
  窓の `*_resets_at` を過ぎた時です (7 日の窓が線に届いている間は、その窓が戻るまで戻りません)
- 移っている間に `fallback` を設定から消した時も、タブは区切りで元の口座へ戻します

## 口座を固定

タブごとに「口座を固定」できます。固定したタブは、**元の口座が線を超えても、元の口座に残ります。** 他のタブが
線で逃げ先へ移る間も、残りの枠を使い続けたい要のタブ (まとめの階層のタブなど) に使います。

- 付け外しは、会話の一覧の各行の ⋯ メニューの「口座を固定」/「口座の固定を外す」です。口座を 2 つ以上設定している
  時だけ出ます。固定したタブは、口座の札の前に 📌 が付きます
- 口は `PATCH /sessions/{タブの id}` の `account_pinned` (`true` / `false`) です。タブの名前や通知の設定を変える口と
  同じです。印はタブの定義 (`session_meta.json`) に保存します。設定ファイルには書きません
- 固定したタブは、見回りも、眠っているタブを起こす時の移し替えも、移しません
- **印が付いた時に逃げ先で動いているタブは、次の区切りで元の口座へ戻します** (線を超えていても)
- [上限が戻った時の続き](limit-resume.md) は、印に関係なく効きます
- 子のタブは、立てた時に親の印を継ぎます。親が逃げ先で動いている時は、子も同じ本来の口座に属して、同じ逃げ先で
  動きます

## 見え方

- 会話の一覧の口座の札は、**今動いている口座**を示します (移っている間は逃げ先)
- 別の機械へ連絡してよいかの判定 ([agent-messages.md](agent-messages.md) の `accounts`) は、**タブの本来の口座**で
  行います。逃げ先へ移っている間だけ送れるようにはなりません
- プッシュ通知は出しません
- backend の log に、移した・戻した・写しを消した、が 1 行ずつ出ます

```
account fallback: moved session=ses_0123456789ab from=work to=personal stopped_by_limit=False continuation_owed=False
account fallback: returned session=ses_0123456789ab from=personal to=work stopped_by_limit=False continuation_owed=False
account move: deleted the record the client wrote path=~/.claude/projects/-path-to-agent/3f2a….jsonl
```

上限で止まったまま残ったタブを、上限が戻った時に続けさせる仕組みは [limit-resume.md](limit-resume.md) です。

## 動かない時

| 見えること | 原因 |
|---|---|
| 移らない | 口座に `fallback` が無い / 警告の出た `fallback` / 設定の後に backend を再起動していない / `rate-limits.jsonl` にその口座の行が無い |
| `account fallback: waits ... reasons=` が出続ける | 区切りに当たっていない。理由は上の表の通り。`turn_open` なら、タブには 1 回だけ区切りを頼んでいる ([答え続けているタブ](#答え続けているタブ)) |
| `account fallback: could not move ...` が出る | 会話を写せない (切れ目がまだ無い等) / `lineage_hook` が失敗した / 移した先で会話を開けなかった。次の回にもう一度試す |
| 戻らない | 元の口座の使用率の行が、まだ線以上で `*_resets_at` が先 / タブが区切りにいない |
| 上限で止まったのに移らない | 会話の最後の行が上の形の行でない (一時的な混雑など)。または元の口座の使用率が線に届いていない |
