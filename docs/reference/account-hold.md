# 口座の止める線

口座の 7 日の使用率か 5 時間の使用率が、操作者が決めた線に届いたら、その口座で動くタブを区切りで止める仕組みです。上限に
当たる前に止めて、残りの枠を取っておくために使います。止めたタブは、**操作者が画面から続けるまで止まったまま**
です。0:00 になっても、使用率が下がっても、自動では再開しません。
ただし、[口座の逃げ先](account-fallback.md) を持つ口座のタブ (この口座へ移ってきたタブと、逃げ先を持つ口座の上で止めたタブ) は、
**どちらかの口座が線を下回ったら、空いた方の口座で自動で続けます** ([どちらかの口座が空いたら](#どちらかの口座が空いたら))。

[口座の逃げ先](account-fallback.md) は、タブを別の口座へ移して動かし続けます。止める線は、タブを止めます。
1 つの口座はどちらか一方です。

既定では何もしません。止めたい口座にだけ、設定を足します。

## 設定

`config.json` の、止めたい口座に `hold` を足します。

```json
"accounts": {
  "personal": {
    "display_name": "Personal",
    "env": {},
    "hold": {
      "five_hour_at_pct": 95,
      "seven_day_at_pct": { "mon": 70, "tue": 76, "wed": 82, "thu": 88, "fri": 94, "sat": 100, "sun": 70 }
    }
  }
}
```

| 項目 | 意味 |
|---|---|
| `five_hour_at_pct` | 5 時間の窓の止める線 (任意)。1 以上 100 以下の整数。既定は無く、書かなければ 5 時間の窓では止めない |
| `seven_day_at_pct` | 7 日の窓の止める線を、曜日ごとに決める表 (任意)。曜日の名前から 1 以上 100 以下の整数への対応 |

`five_hour_at_pct` と `seven_day_at_pct` のどちらか一方は書きます。

- 曜日の名前は `mon` `tue` `wed` `thu` `fri` `sat` `sun` です。**書いていない曜日は、止めません**
- 曜日は backend が動く機械の地方時で決め、0:00 に切り替わります
- 5 時間の窓の線は曜日では変わりません。`five_hour_at_pct` を書かなければ、5 時間の窓は見ません
- 次の `hold` は無いものとして扱い、起動時に log へ警告を 1 行出します
  - `hold` が表でない、`five_hour_at_pct` も `seven_day_at_pct` も無い
  - `five_hour_at_pct` が 1〜100 の整数でない
  - `seven_day_at_pct` が表でない、曜日の名前でない項目がある、値が 1〜100 の整数でない
  - 口座が `fallback` を持っている (逃げ先へ移す口座に、止める線は置けません。`fallback` は残ります)
- 設定は、画面の「設定」から変えられます ([設定の画面](settings-screen.md))。変えた値は、次の見回りから効きます。
  `config.json` を手で書き換えた時は、backend を再起動してください
- 見回りは、[自動の入れ替え](rollover.md) と同じ 60 秒ごとです

## 止める条件

次の**全部**がそろったタブを止めます。

| 条件 | 内容 |
|---|---|
| タブが動いている口座の使用率が、線以上 | その口座の最新の使用率の行 (`rate-limits.jsonl`) で、7 日の使用率が今日の曜日の線以上か、5 時間の使用率が `five_hour_at_pct` 以上のどちらかで、その窓の `*_resets_at` をまだ過ぎていない。線の無い窓は見ない。口座の行が 1 つも無い時は何も言えないので止めない |
| 口座が、そのタブの今動いている口座 | 逃げ先の口座で動いているタブも、その口座の線で止めます。ただし、本来の口座が線に届いていない間は、止めずに本来の口座へ戻します (下) |
| タブが固定されていない | 「口座を固定」したタブは止めません ([口座の逃げ先](account-fallback.md#口座を固定)) |
| タブが眠っていない | 眠っているタブは、止める物がありません |
| タブが止めても壊れない区切りにある | [眠り](sleep.md) の判定を「親が手で眠らせる時」の形で使う |

逃げ先を持つ口座 (止める線は置けません) のタブも、次の時は、その口座の上で同じように止めます ([逃げ先を持つ口座の上で止める](#逃げ先を持つ口座の上で止める))。

区切りの判定は、[口座の逃げ先](account-fallback.md#移す条件) と同じです。当たらないタブは止めず、当たらなく
なった次の回に止めます。上限で止まったタブは、止まったこと自体を区切りとして止めます。

### 逃げ先で動いているタブ

[口座の逃げ先](account-fallback.md) でこの口座へ移ったタブは、この口座が線に届いても、**本来の口座が線に届いていなければ止めません。**
逃げ先の側が、次の区切りでそのタブを本来の口座へ戻します ([逃げ先が線に届いた時](account-fallback.md#逃げ先が線に届いた時))。
本来の口座も線に届いている時と、本来の口座の使用率が分からない時は、このタブも止めます。仕事が止まるのは、本来の口座もこの口座も
線に届いている時だけです。

### 逃げ先を持つ口座の上で止める

逃げ先を持つ口座が [逃げ先の線](account-fallback.md#移す条件) に届き、逃げ先の口座もこの止める線に届いている時は、逃げ先の仕組みは
タブを移しません ([両方が線に届いた時](account-fallback.md#両方が線に届いた時))。その口座で動いているタブは、**その口座の上で止めます。**
条件は、上の表の「タブが動いている口座の使用率が、線以上」を「その口座が逃げ先の線に届き、逃げ先がこの止める線に届いている」に
置き換えた物です。どちらかの口座の行が 1 つも無い時は止めません。

## 止め方

区切りにあるタブを、[眠り](sleep.md) と同じ終わらせ方で眠らせます。会話は、同じ会話のまま起こせます。そして、
タブの定義 (`session_meta.json`) の `held_at` に、止めた時刻 (epoch 秒) を残します。backend を再起動しても残ります。

```
account hold: held session=ses_0123456789ab account=personal stopped_by_limit=False
```

区切りに当たらなかった理由は、同じ理由が続いている間は log に 1 回だけ出ます。

```
account hold: waits session=ses_0123456789ab account=personal reasons=turn_open
```

### 答え続けているタブ

返事を作り続けているタブ (`turn_open`) は、いつまでも区切りに来ません。**区切りに来てくれるよう、client が 1 回だけ
頼みます。** 頼む条件は [口座の逃げ先](account-fallback.md#答え続けているタブ) と同じで、頼んだ時刻はタブの定義の
`hold_asked_at` に残します (backend を再起動しても 2 通目は送りません。使用率が線を下回った時、タブを止めた時に消します)。
連絡は、client の連絡の 1 行目で始まります。

```
Sent by the client (the operator did not type this):
<account-hold phase="stop" account="personal">
Personal の口座の使用量が止める線を超えたので、このタブを止めます。今の作業を区切りの良い所まで進めて、この返事を終えてください。続きは、操作者が画面から続けた時に頼む連絡が届きます
</account-hold>
```

逃げ先を持つ口座のタブ (逃げ先の上で動いているタブと、逃げ先を持つ口座の上で動いているタブ) には、続け方だけが違う文を送ります。

```
Sent by the client (the operator did not type this):
<account-hold phase="stop" account="work">
本来の口座も移す先の口座も使用量が線を超えたので、このタブを止めます。今の作業を区切りの良い所まで進めて、この返事を終えてください。続きは、どちらかの口座が線を下回った時に、client から頼む連絡が届きます
</account-hold>
```

頼んだタブが区切りに来たら、次の見回りが止めます。頼んでから 10 分たっても区切りに来ないタブには、もう送らず、
log に 1 行だけ出します。

```
account hold: asked to stop session=ses_0123456789ab account=personal
account hold: no break after asking to stop session=ses_0123456789ab account=personal waited_sec=612
```

## 続けての連絡を送るタブ

client が「続けて」を送るのは、**続ける仕事が残っているタブだけ**です。タブの定義の `owes_carry_on` がその印で、次の時に立ちます。

- 区切りを頼んだ時 (止める頼み・[移すための頼み](account-fallback.md#答え続けているタブ))。「続きは届きます」と言ったためです
- 上限で止まったタブを止めた・移した時

印は、続けての連絡がタブに届いた時と、タブが起こされた時 (操作者が開いた・連絡で起きた) に消えます。止める時に入力待ちで、印の無かった
タブは、続ける時に**何も送らず、起こさず、`held_at` だけ外します** (log: `account hold: released without a message`)。そのタブは眠ったまま
で、次に起きる時に、動ける口座へ移ってから起きます。

- **頼みはタブに 1 つだけです。** 印が立っている間は、止める頼みも移すための頼みも重ねて送りません。区切りに来た時に、その時の口座の
  状態で、移すか止めるかを決めます
- 区切りを頼んだのに、その後に線を下回って止めも移しもしなかったタブには、区切りに来た時に 1 通送ります (log: `account hold: carried on
  without a stop`)。送れなかった時は印が残り、次の見回りが送り直します

```
Sent by the client (the operator did not type this):
<account-hold phase="continue" account="personal">
区切りを頼みましたが、止めずにこのまま続けます。頼む前の作業を続けてください
</account-hold>
```

## 止まっている間

- 眠っているタブ (止めたタブも、止めていないタブも) へ別のタブから届いた連絡と、[子のタブ](child-sessions.md) が止まった知らせは、
  **そのタブが動ける口座が無い間は、タブを起こさずに預かります。** 動ける口座とは、
  逃げ先を持つ口座のタブなら [続ける](#どちらかの口座が空いたら) 先の口座、それ以外のタブなら線を下回ったタブ自身の口座です。
  線の上の口座でタブを起こして、連絡の返事の分だけ使い続けないためです。送り主の `tabs send` は `預かりました` と出します。
  預かった連絡は、タブの定義の `kept_messages` に来た順に残り (backend を再起動しても残ります)、見回りが次の時に来た順に届けます
  - 動ける口座ができた時 (逃げ先を持つ口座のタブは、続けての連絡の後に)
  - タブが起きている時 (操作者が開いて使っている時など)。起きたタブが区切りにいれば、使用率がまだ線以上なら同じ見回りでまた止まり、連絡は預かったままです

```
account hold: kept a message for a sleeping tab session=ses_0123456789ab account=personal kept=1
account hold: handed over kept messages session=ses_0123456789ab taken=1 left=0
```

- 動ける口座があるタブへの連絡は、今までどおり届きます。届けば、タブは同じ会話のまま起きて (逃げ先を持つ口座のタブは、起きる前に
  動ける口座へ移ります)、`held_at` が消えます (log: `account hold: released ... woken=1`)
- 操作者がタブを開いた時も、タブは起きて `held_at` が消えます。続けての連絡は送りません (続けるかは操作者が決めます)。使用率がまだ線以上なら、そのタブは次の区切りでまた止まります
- 止まっているタブの数は、設定の画面の口座の欄に出ます

## 続ける

続けるのは、操作者です。設定の画面の口座の欄の「全部続ける」を押すと、その口座の `held_at` が付いたタブのうち、
[続ける仕事が残っているタブ](#続けての連絡を送るタブ) には続けての連絡を送って起こし、残りのタブは起こさずに、どれも `held_at` を消します。
口は `POST /accounts/{口座}/continue` です。

```
Sent by the client (the operator did not type this):
<account-hold phase="continue" account="personal">
止めていたタブを続けます。止める前の作業を続けてください
</account-hold>
```

```
account hold: continued session=ses_0123456789ab account=personal
```

- 止まったタブのどれかに動ける口座が無い間は、`409` (`still_at_line`) で断ります。使用率がまだ線 (7 日は今日の線、5 時間は `five_hour_at_pct`) 以上の時、逃げ先を持つ口座で本来の口座も逃げ先も線に届いている時、使用率が分からない (行が無い) 時です。線を上げるか、使用率が戻ってから押してください
- 逃げ先の口座で続けるタブ (本来の口座がまだ線の上) は、ここでは何もしません。見回りが逃げ先へ移して続けます
- 連絡が届かなかった (Claude を起こせない・受け取らない) タブは、`held_at` を残し、答えの `failed` に入れます。もう一度
  押すと、そのタブだけにもう一度送ります
- `hold` を設定から消した口座でも、止まったタブは続けられます (線が無いので、`409` にはなりません。逃げ先を持つ口座を除く)

## どちらかの口座が空いたら

[口座の逃げ先](account-fallback.md) を持つ口座のタブを止めたのは、「本来の口座も逃げ先の口座も線に届いている」ことでした
([逃げ先で動いているタブ](#逃げ先で動いているタブ)・[逃げ先を持つ口座の上で止める](#逃げ先を持つ口座の上で止める))。その後に
どちらかの口座が空いたら、止まったタブは**空いた方の口座で、自動で続けます。** 線に届いている口座は使いません。止める線の目的
(線を超えて使い続けない) とは食い違いません。

| 先に空いた口座 | すること |
|---|---|
| 本来の口座 | 本来の口座で続けます。逃げ先で止まっていたタブは、本来の口座へ戻してから続けます (下の表の条件) |
| 逃げ先の口座 (本来の口座はまだ線の上) | 逃げ先の口座で続けます。本来の口座の上で止まっていたタブは、逃げ先へ移してから続けます。固定したタブは移さず、止まったままです |
| 両方 | 本来の口座で続けます |

本来の口座で続ける条件は、次の**全部**です。逃げ先で続ける条件は、本来の口座が線に届いていて、逃げ先の口座がこの止める線を
下回っている事です (逃げ先の口座の行が 1 つも無い時は続けません)。

| 条件 | 内容 |
|---|---|
| タブが止まっている | `held_at` が付いている。[眠り](sleep.md) の眠りのまま (起きたタブは印が外れるので対象外) |
| タブの本来の口座に、逃げ先 (`fallback`) がある | タブの定義の `fallback_from` が本来の口座か、逃げ先を持つ口座の上で止めたタブ。この口座自身のタブ (逃げ先を持たない口座のタブ) は、自動では続けません。操作者が [続ける](#続ける) |
| 本来の口座が線を下回っている | [口座の逃げ先](account-fallback.md#移す条件) の線と同じ。5 時間が `at_pct` 未満で、7 日が今日の線未満。線に届いていた窓の `*_resets_at` を過ぎていれば、下回っているものとして数える。口座の行が 1 つも無い時は何も言えないので続けない |
| 本来の口座が先回りの線の手前にある | 本来の口座が先回りの線 (`ahead_pct`) に届いている間は、続けません (続けた直後にまた先回りで移す往復を避けるため)。ただし、この口座が止める線に届いている間は、先回りの線に入っていても、線に届いていなければ戻します (逃げ先の線に届いた時の戻し方と同じ) |

戻す時の判定・区切り・冷え待ちは、[口座の逃げ先の戻し方](account-fallback.md#戻す)と**同じ部品**を使います。止まっているタブは眠って
いるので、区切りにあり、キャッシュは冷えています。固定したタブも、本来の口座が線を下回っていれば同じように戻して続けます
(線に届いている間は、固定していても続けません)。

手順は 3 つです。どれも、見回り (60 秒ごと) が行います。

1. タブを空いた方の口座へ移します (今いる口座が空いていれば移しません)。眠っているタブを起こす時に移す手順 ([眠っているタブ](account-fallback.md#眠っているタブ)) と同じです
2. 続けての連絡を送って `held_at` を消します。連絡は、[操作者が続ける時](#続ける) と同じ封筒と同じ口で、口座の欄は続ける口座です。
   続ける仕事の残っていないタブは、1 で移さず、2 で何も送らず、`held_at` だけ外します ([続けての連絡を送るタブ](#続けての連絡を送るタブ))
3. 止まっている間に預かった連絡を、来た順に届けます ([止まっている間](#止まっている間))

```
Sent by the client (the operator did not type this):
<account-hold phase="continue" account="work">
止めていたタブを続けます。止める前の作業を続けてください
</account-hold>
```

```
account hold: resumed on work session=ses_0123456789ab from=personal
account hold: resumed on personal session=ses_0123456789ab from=work
```

- 両方がまだ線に届いている間は、何もしません。タブは止まったままです
- どちらかの口座の使用率が分からない間 (行が 1 つも無い) は、その口座では続けません
- 移せなかった時 (タブが他の処理の最中・移した先で会話を開けなかった) は、タブも `held_at` もそのままで、次の見回りでもう一度
  試します
- 移せたのに連絡が届かなかった時は、`held_at` を残します。次の見回りは、タブを移し直さずに連絡だけをもう一度送ります

## 動かない時

| 見えること | 原因 |
|---|---|
| 止まらない | 口座に `hold` が無い / 警告の出た `hold` / `config.json` を手で書き換えた後に backend を再起動していない / `rate-limits.jsonl` にその口座の行が無い / 今日の曜日に 7 日の線が無く、`five_hour_at_pct` も無い / タブが固定されている / 逃げ先で動いているタブで、本来の口座が線に届いていない (戻される) |
| `account hold: waits ... reasons=` が出続ける | 区切りに当たっていない。理由は [口座の逃げ先](account-fallback.md#移す条件) の表の通り。`turn_open` なら、タブには 1 回だけ区切りを頼んでいる |
| `account hold: not now ... reasons=` が出る | 区切りを読んだ後に、眠らせる直前の確かめで当たった。次の回にもう一度試す |
| 逃げ先を持つ口座のタブが、どちらかの口座が空いても止まったまま | 本来の口座の使用率の行が、まだ線 (先回りの線を含む) 以上で、逃げ先の行もまだ止める線以上 / 空いたはずの口座の行が無い / 本来の口座の `fallback` を設定から消した / 固定したタブで、空いたのが逃げ先 / タブが他の処理の最中 / 移した先でタブの連絡が届いていない (`held_at` が残る。次の回に連絡だけ送る) |
| 止まったタブへの連絡が `預かりました` になる | そのタブが動ける口座が無い。動ける口座ができた時か、タブが起きている時に届く |
| 「全部続ける」が押せない | 使用率がまだ線 (7 日は今日の線、5 時間は `five_hour_at_pct`) 以上 |
| 続けたのにタブが動かない | `failed` に入っている (連絡が届いていない)。もう一度押す |
