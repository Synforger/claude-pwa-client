# 承認の窓を画面へ出す

Claude Code は、道具を使う前に「この命令を実行してよいか」を端末の窓で訊くことがあります (承認の窓)。窓は端末にしか
出ないので、画面でチャットだけを見ていると、窓が開いたまま止まっていることに気づけません。この機能は、窓が開いた
ことを画面と通知で知らせ、画面のボタンや発話で答えられるようにします。

窓は Claude Code 自身のままです。client は窓を作り替えず、閉じもしません。端末で直に答えても、画面で答えても、
同じ窓に同じ答えが届きます。

## 設定

Claude Code の hook に `PermissionRequest` を足し、窓が開く直前の入力を client へ送ります。ほかの hook
([path-a-chat.md](../setup/path-a-chat.md#pwa-連携の-hook-を設定する-チャット表示に必須)) と同じ形で、port は backend に合わせます。

```json
{
  "hooks": {
    "PermissionRequest": [
      { "hooks": [ { "type": "command", "command": "curl -s -o /dev/null -m 2 -X POST http://127.0.0.1:8765/hooks/event -H 'Content-Type: application/json' -H \"X-PWA-SID: ${PWA_SID:-}\" -d @-" } ] }
    ]
  }
}
```

この hook は何も返しません (`-o /dev/null`)。許可も拒否も決めないので、窓はそのまま開き、答えを待ちます。
`AskUserQuestion` と `ExitPlanMode` にも同じ hook が呼ばれますが、client はこの 2 つを窓として画面に出さず、
今までどおり問いと計画の承認の画面で扱います。

hook を足していないタブでは、窓は画面に出ません。`Notification` の通知は今までどおり届きます。

## 画面が見るもの

窓が開いているタブの状態 (`agent_status.pending_permission`) は、窓が無ければ `null`、開いていれば次の形です。

| 欄 | 中身 |
|---|---|
| `number` | 窓ごとに増える番号。答える時に窓を指す |
| `tool_use_id` | 会話の記録の道具の呼び出しの id。まだ結べていない間は `null` |
| `tool_name` | 道具の名前 (`Bash` など) |
| `input` | 窓が訊いている入力の全文。実際に走るのはこちら |
| `record_input` | 会話の記録にある入力。`input` と同じなら `null`。違う時は、hook が入力を書き換えている |
| `index` / `count` | 1 回の応答で窓が続けて開く時の「k / N」 |
| `opened_at` | 窓が開いた時刻 (epoch 秒) |

窓が 2 つ続く時は、Claude Code が会話の記録の呼び出しの順に 1 つずつ出すので、`pending_permission` もいつも一番古い 1 つです。
窓が開いていることは、画面の上部のボタン、タブの一覧の印、通知 (窓 1 つにつき 1 本) で知らせます。

## 窓がまだあるかを決める

窓があるかは、端末の画面で決めます。hook が来ると窓を立て、端末に選択肢の画面 (`1. Yes` / `2. No`) が出たのを
見てから、その窓を「画面に出ている」と数えます。画面に出た後、2 回続けて見えなくなったら閉じます。次の時にも閉じます。

- 窓の道具の結果が会話の記録に書かれた時
- 画面から答えのキーを打った時
- 会話が終わった時 (`Stop`)、新しい会話が始まった時 (`SessionStart`)、タブを再起動した時、口座を移した時

## 答える

```
POST /sessions/{id}/permission/answer
{"number": 3, "answer": "allow"}      // または "deny"
```

| 返事 | 意味 |
|---|---|
| `{"ok": true}` | 答えのキーを 1 つ打った |
| `{"ok": false, "reason": "closed"}` | そのタブの端末に窓が出ていない。何も打っていない |
| `{"ok": false, "reason": "no_yes_line"}` | 許す選択肢の行が見つからない。何も打っていない |
| 409 `permission_stale` | `number` が今の窓ではない (古い窓への答え)。何も打っていない |

打つキーは、打つ直前に端末の画面から選択肢を読んで決めます。ラベルが `Yes` の行が「許す」、`No` の行が「断る」で、
番号は決め打ちしません。`No` の行が無い時の「断る」は Escape です。Enter は打ちません。答えのキーを打ったら、窓は
すぐに閉じた扱いにします。

### 答えの語

人が打った発話の全文が次の語だけの時、窓に出ていれば、発話ではなく窓への答えになります。吹き出しは作らず、
「窓に答えました」を返します。前後の空白と句読点は無視します。

| 語 | 答え |
|---|---|
| 許可 | 許す |
| いいえ・だめ・拒否 | 断る |

「はい」は答えに数えません。エージェントがチャットで訊いた問いへの「はい」と区別できないためです。語が窓に出る前に
届いた時や、端末に選択肢が出ていない時は、答えにせず、次の「窓の間の本文」と同じに預かります。

## 窓の間に打った本文は預かる

端末に本文を打つと、その Enter は窓の最初の選択肢 (`1. Yes`) を確定します。窓の間に別のタブの連絡を打つと、
窓が許可で閉じ、命令が走り、連絡は会話のどこにも残りません。

そこで、承認の窓・計画の承認・問い (`AskUserQuestion`) のどれかが開いている間は、本文を端末に打たずに預かり、
全部閉じたら来た順に打ちます。

- 預かった時の送信の返事は `{"ok": true, "held": "window"}` です
- 別のタブの連絡 ([agent-messages.md](agent-messages.md)) は、送り主に `預かりました` と返します (`届きました` とは言いません)
- 画面から送った本文は、窓が閉じるまで届きません。届かなかった時は、画面の吹き出しが「届かなかった」になります
- 人の Escape と、問いの番号のような 1 つのキーは預かりません。声の割り込みは Escape を打ちません
- 送った本文の確認 ([agent-messages.md](agent-messages.md#claude-が動いていないタブへ送った時)) は、窓の間は Enter を打ち直しません

預かった本文は backend のメモリにあります。backend を再起動すると失われます。

## 窓が開いているタブの扱い

窓の答えは人にしか出せないので、窓が開いているタブは次のように扱います (判定の理由は `permission_open`)。

| 仕組み | 扱い |
|---|---|
| [眠り](sleep.md) | 眠らせない |
| [自動の入れ替え](rollover.md) | 締めを頼まない。入れ替えの途中の数にも入れない |
| [口座の振り分け](account-fallback.md)・[止める線](account-hold.md) | 区切りと見なさず、移さず、止めず、区切りを頼む連絡も送らない |
| [子のタブの見回り](child-sessions.md#止まった子の見回り) | 窓が 5 分続いた子を、親に 1 回知らせる |

## 困った時

| 症状 | 見る所 |
|---|---|
| 窓が開いているのに画面に出ない | `PermissionRequest` の hook を足したか。タブを起動し直した後か (hook は起動時に読まれる) |
| 画面で答えても `closed` が返る | 端末に選択肢が出ていない。窓が出てから答える |
| 答えを打ったのに窓が残る | 端末の画面を見る。窓が選択肢の形でない時は、画面から打たず端末で答える |
| 預かった本文が届かない | 窓・計画の承認・問いが残っていないか。全部閉じると届く |
